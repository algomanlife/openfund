# Openfund Protocol — future product

> Openfund Protocol is designed to aggregate liquidity across Gains Network, Hyperliquid, and dYdX, enabling intelligent trade routing and improved execution-path selection. (Available in the final release.)

This is product intent, not a guaranteed release promise. **Source foundation: Completed within repository scope. Operational routing: Planned.** `packages/openfund-protocol/` already contains integrated dormant Solidity source, provenance, configuration and compile/test foundation. No active aggregation, quote comparison, routing or transaction execution is established. A documentation refresh must preserve the source and licensing without treating it as a production venue.

## Phase 6 gates

P1 in [Milestones](MILESTONES.md) covers protocol architecture, venue capability contracts, source/license provenance, risk authority and failure semantics. P2 covers validated venue adapters, comparable execution information, route selection, stale-source handling, user confirmation and settlement reconciliation. P1's source/provenance foundation is integrated; operational adapter/risk acceptance and P2 routing remain planned. Dates and performance improvements are not promised.

The current Gains read integration, Prop simulation, wallet sessions and charting foundation retain their existing responsibilities. Future routing must not be drawn as an implemented connection or reuse a simulated balance as real liquidity.
