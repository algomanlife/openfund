# Openfund Protocol — future product

> Openfund Protocol is designed to aggregate liquidity across Gains Network, Hyperliquid, and dYdX, enabling intelligent trade routing and improved execution-path selection. (Available in the final release.)

This is the intended final-release product description. **Current status: Planned.** No operational aggregation, routing, quote comparison or transaction execution is delivered by this documentation task. No Openfund Protocol or other protocol source is imported, copied or integrated here. Source integration belongs to the separately scoped Task 2.

## Phase 6 gates

P1 in [Milestones](MILESTONES.md) covers protocol architecture, venue capability contracts, source/license provenance, risk authority and failure semantics. P2 covers validated venue adapters, comparable execution information, route selection, stale-source handling, user confirmation and settlement reconciliation. Both remain planned; dates and performance improvements are not promised.

The current Gains read integration, Prop simulation, wallet sessions and charting foundation retain their existing responsibilities. Future routing must not be drawn as an implemented connection or reuse a simulated balance as real liquidity.
